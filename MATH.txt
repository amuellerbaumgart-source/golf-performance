GOLF PERFORMANCE EXPERIMENTS — MATHEMATICS REFERENCE
=====================================================

Purpose
-------

This file describes the calculations currently implemented by the app and
the statistical improvements still planned for later phases. It is intentionally
separate from the README so that the assumptions and formulas can be
reviewed without reading the Streamlit UI.

The central experiment is an A/B comparison:

    A = baseline configuration
    B = treatment configuration

Only one golf variable should change between A and B.


1. Metric analysis scale
------------------------

The app first converts raw entered values to an analysis scale.

Raw metric:

    x_analysis = x

Absolute-value metric, such as offline distance:

    x_analysis = |x|

Target metric, such as launch angle or spin:

    x_analysis = |x - target|

For target metrics, lower absolute error is better. The target itself is
not treated as a second observed condition; the distance from the target is
the quantity being compared.

Invalid, non-numeric, NaN, and infinite values are excluded from the
calculation and reported as warnings.


2. Descriptive statistics
-------------------------

For each configuration, the app reports the number of valid observations,
mean, median, and sample standard deviation.

For observations x_1, ..., x_n:

    mean = (x_1 + ... + x_n) / n

    median = middle ordered value

    sample variance = sum((x_i - mean)^2) / (n - 1)

    sample standard deviation = sqrt(sample variance)

The n - 1 denominator is used because the observations are treated as a
sample rather than the complete population of all possible shots.

The current implementation reports these statistics at the individual-shot
level.


3. Observed difference
----------------------

The current difference is always calculated as treatment minus baseline:

    difference = mean(B) - mean(A)

This raw difference is intentionally not direction-adjusted in the
statistics module. The decision module interprets the sign using the metric
direction.

For a non-zero baseline mean, the current percentage difference is:

    percentage_difference =
        (mean(B) - mean(A)) / |mean(A)| * 100

When mean(A) is zero, percentage difference is unavailable because the
denominator is zero.


4. Legacy inferential analysis: Welch's t-test
------------------------------------------------

CURRENT METHOD

When analysis is called without a protocol, the compatibility path uses a
two-sided Welch independent two-sample t-test. Its explicit metadata is:

    statistical_method = welch_independent_two_sample_t
    analysis_unit = individual_shot

This method does not assume equal variances between A and B, but it does
assume that observations are independent within and between conditions.

For the current method:

    SE = sqrt(s_A^2 / n_A + s_B^2 / n_B)

    t = (mean(B) - mean(A)) / SE

The Welch-Satterthwaite degrees of freedom are:

    df =
      (s_A^2/n_A + s_B^2/n_B)^2 /
      [ (s_A^2/n_A)^2/(n_A - 1)
        + (s_B^2/n_B)^2/(n_B - 1) ]

The two-sided p-value is calculated from the t distribution with this
degrees-of-freedom value.

The 95% confidence interval is:

    difference +/- t_(0.975, df) * SE

At least two valid observations per configuration are required for these
current inferential statistics.

IMPORTANT LEGACY LIMITATION

The app's actual testing protocol uses repeated shots from one golfer in
alternating blocks. Those shots are unlikely to be fully independent due to
fatigue, learning, order, and environmental effects. Therefore, the current
shot-level Welch result can overstate the effective amount of information.

The protocol-aware application workflow no longer uses this method as its
primary analysis. It remains available for compatibility with direct callers
and legacy analysis fixtures.


5. Legacy effect size: independent-group Hedges' g
---------------------------------------------------

The current implementation uses a pooled standard deviation:

    s_pooled = sqrt(
        ((n_A - 1)s_A^2 + (n_B - 1)s_B^2)
        / (n_A + n_B - 2)
    )

Cohen's d is:

    d = (mean(B) - mean(A)) / s_pooled

The small-sample correction is:

    J = 1 - 3 / (4(n_A + n_B - 2) - 1)

Hedges' g is:

    g = J * d

This is appropriate as an effect-size summary for the legacy independent
two-group calculation. The protocol-aware primary analysis uses a paired
effect size instead.


6. Practical significance
-------------------------

Statistical significance and practical significance are evaluated
separately.

For a higher-is-better metric:

    observed_improvement = difference

For a lower-is-better metric:

    observed_improvement = -difference

For target metrics, the analysis scale is absolute error from target, so
the metric is evaluated as lower-is-better:

    observed_improvement = -difference_in_absolute_error

For an absolute practical threshold T:

    practically_meaningful = observed_improvement >= T

For a percentage threshold P:

    practically_meaningful = observed_improvement_percentage >= P

The current decision rule for statistical significance is:

    statistically_significant = p_value < alpha

with alpha = 0.05 by default.

The app does not use p < 0.05 as its only decision rule. It combines the
statistical result with the predefined practical threshold.


7. Current power calculation: paired blocks
----------------------------

The protocol-aware power method is explicitly:

    method = paired_block_t

The practical threshold is treated as the effect worth detecting:

    expected_effect = practical threshold in measurement units

The standardized effect is:

    standardized_effect = expected_effect / expected_standard_deviation

The sample-size calculation uses a paired one-sample t-test power model on
paired A/B block differences with:

    alpha = 0.05
    target power = 0.80
    two-sided alternative

The expected individual-shot SD is converted to an estimated block-difference
SD using:

    expected_block_difference_SD
        = expected_shot_SD * sqrt(2 / block_size)

The raw result is a number of paired block comparisons. It is rounded upward
to a whole number of block pairs and then converted to shots:

    recommended_shots_per_configuration
        = recommended_block_pairs * block_size

Achieved power is recalculated after rounding the sample size upward.

The conversion from shot SD to block-difference SD assumes roughly
independent shots within blocks. It is a planning approximation and can be
optimistic when shots are autocorrelated.

Power is not a guarantee that a result will be statistically significant.
It is the probability of detecting the specified effect under the chosen
model if that effect and its variability are approximately correct.


8. Current minimum detectable effect
-------------------------------------

For a selected number of shots per configuration, the current MDE converts
the shots into paired block pairs and solves the paired power equation for the
smallest standardized effect producing the target power.

The result is converted back to measurement units:

    MDE = standardized_MDE * expected_block_difference_SD

The current MDE therefore inherits the shot-SD-to-block-SD planning
approximation.


9. Primary method: paired block analysis
---------------------------------------------

The protocol-aware analysis uses the protocol's block structure.

For each A/B block pair:

    A_block_mean = mean of the A shots in the block
    B_block_mean = mean of the B shots in the block

    paired_difference_i = B_block_mean_i - A_block_mean_i

The paired block difference, rather than every individual shot, becomes
the primary inferential unit.

For k paired block differences:

    mean_difference = mean(paired_difference_i)

    SE = sd(paired_difference_i) / sqrt(k)

    df = k - 1

    t = mean_difference / SE

The 95% confidence interval will be:

    mean_difference +/- t_(0.975, k - 1) * SE

The paired effect size uses the standard deviation of the paired differences:

    d_z = mean_difference / sd(paired_difference)

    J = 1 - 3 / (4(k - 1) - 1)

    paired Hedges' g = J * d_z

The paired t-test requires at least two complete block pairs. The app keeps
the shot-level A and B summaries for descriptive context, but reports the
paired block count separately as the inferential sample size.

This method is necessary because the current protocol creates matched time
blocks. It avoids presenting every repeated shot as an independent
replication unit.


10. Power approximation for the pilot
----------------------------------------------

Before data exists, a golfer may know or estimate individual-shot SD but
usually will not know the SD of paired block differences.

The pilot approximation uses:

    estimated_SD_block_difference
        = estimated_shot_SD * sqrt(2 / shots_per_block)

This assumes approximately independent shots within each block and similar
variability in A and B. The app will label this as a planning approximation.

After data is collected, the actual SD of paired block differences will be
calculated and compared with the planning estimate.

Positive within-block autocorrelation, fatigue, or learning can make the
approximation optimistic. The report will warn about this limitation.


11. Bootstrap sensitivity analysis
----------------------------------

The app resamples the observed paired block differences
with replacement.

For each bootstrap replicate:

    sample k paired differences with replacement
    calculate their mean

The 2.5th and 97.5th percentiles of the bootstrap means will form a
sensitivity 95% interval.

The paired t interval remains the primary inferential interval because it is
simple to explain. The bootstrap interval is a robustness check, especially
for skewed or non-normal block differences. The bootstrap uses a fixed seed
for reproducible reports and is shown only when at least five complete block
pairs are available.


12. Confirmatory and exploratory interpretation
-----------------------------------------------

The primary metric is selected before results are reviewed and is the only
metric treated as confirmatory.

Secondary metrics remain useful for identifying tradeoffs, but their
inferential results are exploratory/descriptive. Showing a nominal p-value
for a secondary metric does not make it a confirmatory finding. The report
labels secondary results as exploratory and warns that their nominal
p-values should not be interpreted as independent confirmatory evidence.

This avoids treating many simultaneous p-values as though they were one
predefined hypothesis test.


13. Worked current example
--------------------------

Suppose:

    A mean = 100.25 yards
    B mean = 105.50 yards
    A SD = 1.7078 yards
    B SD = 1.2910 yards
    n_A = n_B = 4

Then:

    difference = 105.50 - 100.25 = 5.25 yards

    percentage difference = 5.25 / 100.25 * 100
                         approximately 5.2369 percent

The current Welch test calculates uncertainty using the two independent
sample variances and reports a two-sided p-value and 95% interval.

This example demonstrates the current calculation only. It does not remove
the need for the planned block-aware analysis when the observations came
from repeated shots by one golfer.


14. Interpretation rules
------------------------

The app should communicate all of the following separately:

    magnitude: how large was B - A?
    uncertainty: how wide is the confidence interval?
    statistical evidence: what does the chosen test indicate?
    practical relevance: did the effect exceed the predefined threshold?
    design limitations: how many independent units were actually observed?

The app should not reduce these dimensions to the statement "B is better."
