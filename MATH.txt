GOLF PERFORMANCE EXPERIMENTS — MATHEMATICS REFERENCE
==================================================

Compare A (baseline) with B (treatment), changing one golf variable at a
time. The primary analysis compares matched A/B blocks; individual-shot
statistics describe the shots themselves. The question is: how much did B
change performance, and how certain are we about that change?

There are two calculation paths:

    With a testing protocol: compare paired blocks (the primary method).
    Without a protocol: compare individual shots (the legacy method).

"Legacy" means an older calculation retained so existing code and data
can still be analyzed without supplying a protocol. It is implemented,
not a planned feature, and is not the primary method for block experiments.


1. Prepare and summarize the data
--------------------------------

Convert each entered value x to the metric's analysis scale:

    Raw metric:        x
    Absolute metric:   |x|          (e.g., offline distance)
    Target metric:     |x - target| (e.g., launch angle)

The bars | | mean absolute value: ignore the sign. Thus, shots 5 yards left
and 5 yards right both have an offline distance of 5 yards. A launch angle
of 14 degrees with a target of 12 degrees has an error of 2 degrees.
For target metrics, lower error is better.

Invalid or non-numeric values, NaN (a missing or undefined number), and
infinite values are excluded and reported as warnings.

For each configuration, report the valid shot count n and:

    mean = sum(x_i) / n
    median = middle ordered value (average the middle two if n is even)
    sample SD = sqrt(sum((x_i - mean)^2) / (n - 1))

Here, x_i is one analyzed shot value, sum means add all values, and sqrt
means square root. The mean is the average; the median is the midpoint.
Standard deviation (SD) describes how widely shots vary around the mean,
in the metric's own units. Larger SD means less consistency. Dividing by
n - 1 corrects the variance estimate for using a sample; SD needs two shots.


2. Difference and practical significance
---------------------------------------

At the shot level:

    shot_difference = mean(B) - mean(A)

The primary analysis instead uses the average difference across complete
block pairs (Section 3). These differences agree when all equal-sized
blocks are complete; excluding a pair can make them differ. Percentage
change uses the selected analysis difference and the valid A-shot mean:

    percentage_difference = difference / |mean(A)| * 100

Percentage change is unavailable when mean(A) is zero. With all equal-sized
blocks complete, means of 100.25 and 105.50 yards give +5.25 yards, or
about +5.24%.

Interpret the sign according to the metric:

    Higher is better:  improvement = difference
    Lower is better:   improvement = -difference

Target metrics use the lower-is-better rule on absolute error. An effect
is practically meaningful when improvement meets the predefined absolute
threshold T, or its percentage improvement meets the percentage threshold P,
depending on the threshold selected before testing. For example, if an
extra 3 yards is your minimum worthwhile gain, a 1-yard gain does not meet
that threshold even if it is statistically significant.

Statistical significance is evaluated separately:

    statistically_significant = p_value < alpha  (default alpha = 0.05)

A p-value asks: if there were no average A/B difference and the model's
assumptions held, how likely would a result at least this extreme be?
It is not the probability that B is better or that the result is "due to
chance." Alpha is the cutoff chosen for declaring statistical significance.
A decision considers both statistical evidence and practical relevance.
The practical check applies to the observed estimate. A significant p-value
and an estimate above the threshold do not establish that the true effect
exceeds that threshold: the test compares the effect with zero, not with
the practical threshold. Read the confidence interval to assess uncertainty
in the size of the improvement.


3. Primary method: paired block analysis
---------------------------------------

A block is a consecutive group of shots using one configuration. The
protocol pairs adjacent A and B blocks so each comparison is made close
in time. New plans balance A-then-B and B-then-A pairs and randomize their
order before data collection. With an odd number of pairs, the counts
differ by one. The experiment ID makes the plan reproducible; saved plans
keep their exact sequence. Older saved plans retain their original order.

Balancing prevents one setup from always going second. It can offset a
constant within-pair order effect, but cannot eliminate changing fatigue,
carryover from the previous setup, or dependence between pairs. Keep
separate block IDs even when the same setup ends one pair and starts the
next. For example, five A shots followed by five B shots
produce one paired comparison, not ten independent comparisons.

Both blocks must contain the required number of valid values for the
metric. Otherwise, that pair is excluded from the paired analysis.
For each complete pair, calculate:

    d_i = mean(B shots in block i) - mean(A shots in block i)

With k pairs and s_d = sample SD of their differences:

    mean_difference = mean(d_i)
    SE = s_d / sqrt(k)
    df = k - 1
    t = mean_difference / SE
    95% confidence interval = mean_difference +/- t_(0.975, df) * SE

SD describes variation among pair differences; standard error (SE)
describes uncertainty in their estimated average. More independent pairs
usually reduce SE. The t statistic expresses the average difference in
units of SE: a larger absolute t is stronger evidence against zero change.

Degrees of freedom (df) determine the shape of the t distribution, which
allows for uncertainty in the estimated SD. The multiplier t_(0.975, df)
leaves 2.5% in each tail. "Two-sided" means the test considers changes in
either direction. At least two complete pairs are required.

A 95% confidence interval shows the range supported by this procedure.
Across repeated experiments satisfying the assumptions, about 95% of
intervals constructed this way would contain the true average difference.
A wide interval means the effect is still imprecisely estimated.

The paired effect size standardizes the difference and corrects for a
small sample. Unlike a difference in yards or degrees, this is unitless:

    d_z = mean_difference / s_d
    J = 1 - 3 / (4(k - 1) - 1)
    paired Hedges' g = J * d_z

Paired Hedges' g requires at least three complete pairs. With only two,
the correction J becomes zero, so the app reports the effect size as
unavailable and explains why. The mean difference, t-test, and confidence
interval remain available when variability is nonzero.

For example, d_z = 1 means the average difference equals one SD of the
pair differences. J reduces the small-sample tendency to overestimate the
standardized effect. Practical importance still depends on your threshold.

The inferential sample size is k block pairs, not the number of shots.
Matching blocks accounts for the protocol's time structure without treating
every repeated shot as an independent replication. It still assumes pair
differences are independent of one another and, especially with few pairs,
approximately normally distributed (following a symmetric, bell-shaped
pattern). Pairing does not remove every effect of fatigue, learning, or
changing conditions.

Bootstrap sensitivity analysis

With at least five complete pairs, resample k paired differences with
replacement (a difference can be selected more than once) and calculate
their mean repeatedly. Keeping the middle 95% of these means gives a
second interval, bounded by the 2.5th and 97.5th percentiles. A fixed random
seed repeats the same resampling choices, making the result reproducible.
This checks whether the interval changes substantially with a different
method; the paired t interval remains primary. Resampling does not create
new evidence or fix dependence between pairs.


4. Power and minimum detectable effect
--------------------------------------

Planning uses a two-sided paired t-test model (method = paired_block_t),
with default alpha = 0.05 and target power = 0.80.

Power is the probability of detecting a specified real effect under the
model. Here, detection means rejecting zero change, not establishing that
the true effect exceeds the practical threshold. At 80% power, about 80 out of 100 repeated experiments would flag
that effect as statistically significant if the planning assumptions held.

Prefer the sample SD of paired differences from a separate, comparable
pilot: calculate B-block mean minus A-block mean for each pair, then take
the sample SD of those differences. Use the same block size, order design,
and analysis scale as the planned experiment. Enter SD, not standard error. A small
pilot gives an uncertain estimate; also examine a plan with a larger SD.

If no pilot estimate is available, approximate variability from shot SD:

    estimated_block_difference_SD
        = estimated_shot_SD * sqrt(2 / shots_per_block)

    standardized_effect
        = practical_threshold_in_measurement_units
          / planning_block_difference_SD

Here, planning_block_difference_SD is the supplied pilot SD or the
shot-based estimate above. Averaging shots reduces variability under the
independence assumption;
the factor 2 accounts for subtracting two equally variable block means.

Solve the power equation for the required number of block pairs, round up
to at least two pairs, and convert to shots:

    recommended_shots_per_configuration
        = recommended_block_pairs * shots_per_block

Achieved power is recalculated after rounding. For a chosen shot count,
convert to block pairs and solve for the smallest effect detectable at the
target power. This is the minimum detectable effect (MDE):

    MDE = standardized_MDE * planning_block_difference_SD

MDE describes the experiment's sensitivity, not the smallest effect that
matters to you or a guarantee that smaller effects will go undetected.

The SD conversion assumes independent shots within blocks, equal A/B shot
variances, and zero covariance between paired block means. In general:

    Var(B_mean - A_mean) = Var(B_mean) + Var(A_mean)
                          - 2 * Cov(A_mean, B_mean)

Covariance describes how the two means move together. The approximation
omits that term and uses shot variance / block size for each mean. Actual
block-difference SD can be higher or lower. A supplied pilot SD bypasses
this conversion and is used consistently for sample size, achieved power,
and MDE. Both approaches still assume independent differences across pairs;
neither corrects order bias or guarantees the requested power.


5. Legacy method: independent shots
----------------------------------

The legacy calculation puts all valid A shots in one group and all valid
B shots in another, ignoring their order and block pairing. It applies a
two-sided Welch t-test to the difference between those group means.

The analysis function selects it only when no testing protocol is supplied
(protocol=None). Its purpose is compatibility with older or direct calls
that supply shot data alone. The report identifies this path as:

    statistical_method = welch_independent_two_sample_t
    analysis_unit = individual_shot

It requires at least two valid shots per configuration and assumes
independent observations: knowing how one shot deviated should not help
predict another shot's deviation. It allows A and B to have different
variances (variance is SD squared). With small samples, each group's values
should also be approximately normally distributed. Using shot counts n_A,
n_B and sample SDs s_A, s_B:

    SE = sqrt(s_A^2 / n_A + s_B^2 / n_B)
    t = (mean(B) - mean(A)) / SE

    Welch-Satterthwaite degrees of freedom:
    df = (s_A^2/n_A + s_B^2/n_B)^2 /
         [(s_A^2/n_A)^2/(n_A - 1) + (s_B^2/n_B)^2/(n_B - 1)]

    95% confidence interval = difference +/- t_(0.975, df) * SE

The two-sided p-value uses the t distribution with these degrees of freedom.
The legacy effect size uses a pooled SD, a weighted combination of the
two groups' shot variability:

    s_pooled = sqrt(((n_A - 1)s_A^2 + (n_B - 1)s_B^2)
                    / (n_A + n_B - 2))
    d = difference / s_pooled
    J = 1 - 3 / (4(n_A + n_B - 2) - 1)
    Hedges' g = J * d

Repeated shots from one golfer may be correlated, so this method can
overstate the information available, making confidence intervals too narrow
and p-values too small. For example, a run of shots affected by fatigue
does not provide as much independent information as its shot count implies.

Welch's test is useful for genuinely independent groups. The reason to use
paired blocks here is the experiment's structure, not that Welch's test is
universally inferior. The paired and legacy Hedges' g values also use
different SDs, so they should not be compared as interchangeable effect sizes.

For either method, the formulas involving division by SD or SE require
nonzero variability. If variability is zero but the difference is nonzero,
the app reports the inferential results as unavailable. If both are zero,
it returns a [0, 0] interval and p = 1 as a software convention. It also
returns g = 0, except that paired g remains unavailable with only two pairs;
this does not establish that future shots will have no variability.


6. Interpret the results
-----------------------

Choose the primary metric before reviewing results. It is labeled
confirmatory only when the selected plan is confirmatory, meaning it tests
the question specified in advance. In an exploratory plan, every metric
is labeled exploratory, including the primary metric. Secondary metrics are
exploratory: they reveal possible tradeoffs or questions for a later test.
Their nominal p-values are calculated separately, without adjustment for
examining multiple metrics. Looking at many metrics increases the chance
of finding a small p-value even when no real effect exists.

Report effect magnitude, confidence interval, statistical evidence,
practical relevance, and design limitations separately. A single statement
such as "B is better" does not capture all five.
